## The two genuine members

- **`gate-runner-harness-marker-coupling.mjs`** — locates a real call site in `scripts/test-daemon.mjs` via `src.split("\n").find((l) => l.includes(callPrefix) && needles.every((n) => l.includes(n)))`: a single-line needle locator, not AST, not comment-stripped, not whitespace-normalized. A comment landing on (or itself forming) a line satisfying the needles can make `.find()` resolve the wrong line, breaking the subsequent template-literal extraction. So can a bare NEWLINE with no comment at all: inserting one right after `callPrefix` moves the rest of the call onto a different line, so `.includes(callPrefix)` and the needle checks no longer both hold on the SAME line — verified directly against the real `extractTemplateLiteral` function (a synthetic before/after pair: the unmodified call is found; the same call with a newline inserted after `console.error(` is not).

- **`test-daemon-codex-real-spawn-preset.mjs`** — asserts `scriptSource.includes("resolveSelectionForCliMode(HERMETIC, cliMode, CODEX_REAL_SPAWN_BASENAMES)")` against the real `scripts/test-daemon.mjs` text.

## Correction to `CHANGED_TS_TEXT_SCANNER_REPO_PATHS`'s own shape-(4) doc: it previously claimed a false immunity, in two ways

That array's shape-(4) entry (`loopback-secret.mjs`'s `/timingSafeEqual\(/` presence check) previously claimed a single-token regex like this one "has no internal position for a comment to land" and was therefore immune, and ALSO named `test-daemon-codex-real-spawn-preset.mjs` as "the same shape one level up" and therefore immune too. Both claims are MEASURED FALSE, for two different, independent reasons. Code Review on this card caught both.

**Reason 1 — `loopback-secret.mjs` (D) itself is a known, pre-existing fail-open vector for an inline comment, not a whitespace-only edit.** Verified directly with `ts.transpileModule`, comparing REAL tsc emit (comments preserved, matching this repo's tsconfig — no `removeComments` anywhere in it) for three variants of `timingSafeEqual(a, b);`:

```js
const ts = require('typescript');
const opt = { compilerOptions: { target: ts.ScriptTarget.ESNext } }; // real emit shape: comments kept
const before = 'timingSafeEqual(a, b);';
const afterInline = 'timingSafeEqual /* c */(a, b);';
const afterNewline = 'timingSafeEqual\n(a, b);';
ts.transpileModule(before, opt).outputText;       // "timingSafeEqual(a, b);\n"
ts.transpileModule(afterInline, opt).outputText;  // "timingSafeEqual /* c */(a, b);\n"  <- comment SURVIVES
ts.transpileModule(afterNewline, opt).outputText; // "timingSafeEqual(a, b);\n"          <- newline VANISHES
```

Real tsc emit REPRINTS from the parsed AST rather than preserving source bytes verbatim, so a bare newline (no comment) does not survive into the compiled output — both the before and after source reprint to the byte-identical emitted text, and `/timingSafeEqual\(/` matches both. A COMMENT, by contrast, is trivia tsc keeps attached to its nearest node, so it DOES survive into the emit and breaks the regex on the "after" variant while leaving it matching on "before". The corrected doc entry states this as a KNOWN, PRE-EXISTING fail-open vector in `loopback-secret.mjs` (D) for an inline-comment diff specifically — not fixed by this card, tracked on a separate follow-up card the reviewing lead is filing. Do not cite this shape as evidence of immunity going forward.

**Reason 2 — `test-daemon-codex-real-spawn-preset.mjs` fails for a further, independent reason: a `.mjs` script has no compile/emit step at all.** Its raw scanner reads the committed FILE'S BYTES DIRECTLY (`fs.readFileSync`), with no AST-reprint step to normalize whitespace away the way real tsc emit does for `dist/**` (Reason 1's mechanism). So BOTH a comment AND a plain WHITESPACE-only edit (an added newline, altered internal spacing) survive unchanged into what this scanner reads — confirmed both by the direct `ts.transpileModule` comparison for the comment case (a comment inserted between `HERMETIC,` and `cliMode` transpiles identically at `removeComments:true` while breaking the raw `.includes()` substring) and, independently, by the newline test against `gate-runner-harness-marker-coupling.mjs`'s own needle locator above. This is the general property that makes BOTH scripts-list members genuine: unlike a `dist/**`/`src/**` reader, a `scripts/**` raw scanner has no compiler standing between the committed source and what it reads, so it is vulnerable to whitespace-only diffs as well as comment-only ones — a strictly WIDER exposure than the `dist/**`/`src/**` population `CHANGED_TS_TEXT_SCANNER_REPO_PATHS` covers.

Both files are therefore genuine members of `CHANGED_SCRIPT_TEXT_SCANNER_REPO_PATHS`, not exclusions.

## DoD-2: a new list, on a new trigger — not folded into the existing one
