# 4cbbc343 — the trust class follows the LISTENER; trusted-proxy mode is a third, loopback-only listener

Card `4cbbc343` (owner chose "B — build trustedProxyOrigins", request `9bf644c5`), folding in `d0f3c8ea`. Builds on `23496950` (the remote listener is a separate server; loopback stays plain HTTP on PORT). Design reviewed by a Code Reviewer before any code; finding C1 (below) reshaped it.

## Decision

- ONE predicate, `requestClass` (`gateway/trust-tier.ts`), decides a request's trust class: `loopback`, or `remote` via `peer` (a non-loopback or undeterminable TCP peer), `remote-listener`, `proxy`, or `forwarded`. No other file reads a peer address or compares to a loopback literal (`test/remote-trust-single-predicate-guard.mjs`). Every trust decision reads it: the CSRF/Origin/Host hook, the tier wall, the loopback-secret guard, `/ws/term` read-only + no-host-shell (`710a34fa`), the six `/internal/*` routes, and the rate-limit keys.
- **The class follows the LISTENER, never a Host header (review finding C1).** Classifying by Host fails OPEN: a proxy that rewrites Host to its upstream (nginx's default), or a client-chosen `Host: 127.0.0.1:4317`, would be served as loopback — every ungated loopback GET and `/ws/fleet` without a token, i.e. the rejected "just allowlist the Host" option. So proxy mode is a THIRD listener, `remoteAccess.proxyPort`, bound to `127.0.0.1` only, with NO default (nothing listens until a human sets it). Every request/upgrade on it is marked (WeakSet on the raw request, set before `app.routing` and in the upgrade forwarder) and is remote-class whatever its Host, peer or headers.
- `d0f3c8ea`: every request on the REMOTE listener is likewise marked remote-class, even from a loopback peer (a same-host dial of the internet-facing port no longer borrows loopback trust). Answer: yes.
- On the proxy listener: the Host must equal a `trustedProxyOrigins` entry (canonical host + port, the entry scheme's default port applied; trailing-dot and userinfo refused) and an Origin, if present, must be THAT SAME entry (`null` and empty refused). A `Tailscale-Funnel-Request` header is refused on every route. On the daemon's own PORT the class still follows the PEER: a proxy Host there still 403s, and a loopback peer carrying `X-Forwarded-*`/`Forwarded`/`Via`/`X-Real-IP`/`Tailscale-*` while proxy mode is configured is classed remote (`forwarded`) — a downgrade only. That is NOT a guarantee: a proxy that rewrites Host to `127.0.0.1:<PORT>` and adds none of those headers (nginx's default `proxy_pass`) is indistinguishable from a local client and is served as loopback, so the docs say never to point a proxy at PORT (pinned by `remote-trusted-proxy.mjs` (3) LIMIT).
- One source of truth for "is remote trust live": `resolveRemoteTrust` (wall registration, proxy mode, canonical origins). Fail-closed: a request classed remote while NO wall is registered is refused 403 (a determinable peer only) — the loopback-secret guard's skip for non-loopback callers is safe only because "remote ⇒ the wall is on".
- Config is HUMAN-only (`remoteAccess.proxyPort`, `remoteAccess.trustedProxyOrigins`, in the shared `remoteAccessOverride`, so both the override and patch schemas carry it; the agent project-config shape rejects `remoteAccess`). Entries are exact canonical origins: no wildcard, path, userinfo, trailing dot, loopback or ambiguous host; https unless `.ts.net`; max 16. Proxy mode needs `remoteAccess.enabled` (one master switch), a valid entry and a gateway token; a config change needs a daemon restart. Without a gateway token at boot the daemon STILL BOOTS: the proxy listener is simply not opened and a WARN says why, so minting the first token needs a restart (never described as "refuses to boot").
- Rate limiting for the proxy class is THROTTLE-ONLY and VERIFY-FIRST: every caller shares one local socket address, so a per-ip lockout would let one guesser lock out the owner (and tokens are 256-bit, so a lockout adds nothing). A valid token is gated only by its own per-token cap; presented-but-invalid tokens are throttled (429) on the failure path only; a generous shared pre-auth cap covers unauthenticated requests. The webhook ingress is not reachable through this listener.
- The SPA shell is public to the proxy class ONLY (owner flag F1, recommended by the design review): a browser must load the app before it can present a token. It is keyed on the MATCHED route pattern — `GET|HEAD /*`, the one route `@fastify/static` registers, which matches only what no daemon route matched — never on the request path text (`isStaticShellRoute`). Every non-shell route still needs the token; the remote listener stays API-only; it is deliberately NOT rate-limited (security review 3d70a0a9): it is public static bytes, and every proxied request arrives from 127.0.0.1, so any shared bucket would let one tailnet peer 429 the owner's own app load — the API throttles are unchanged. The static registration sets `dotfiles: "ignore"` so a dotfile in the web dist can never be fetched through it. The web side keeps the GATEWAY token in its own storage key (`loom.gatewayToken`, captured from `?gwtoken=`), sends it on every request and in the ws double-subprotocol, and shows its own banner keyed on `code:"gateway-token-required"`. A `?gwtoken=` link is VERIFIED against `/api/version` before it is stored (a refused link never overwrites a working token and is surfaced instead) — the loopback credential banner (`093981dd`) is untouched.
- Tier-1 only, like any remote caller: a Serve cockpit is reads + answer/steer + view-only terminals; every Tier-0 page (config, writers) 403s.

## Do not

- Do not classify a request by its Host, Origin, `X-Forwarded-*` or any header a proxy may rewrite or a client may choose; the class is the listener (or the socket peer).
- Do not read a peer address or compare to a loopback literal outside `requestClass`; do not re-derive "is remote trust on" outside `resolveRemoteTrust`.
- Do not add a wildcard/suffix to `trustedProxyOrigins`, accept a loopback entry, bind the proxy listener to anything but 127.0.0.1, give `proxyPort` a default, or make either key agent-writable.
- Do not add a hard lockout (or a per-ip key) to the proxy class, or verify a token AFTER a throttle.
- Do not widen the shell exemption past `GET|HEAD /*` or to any class but the proxy listener, and do not decide it from the path text.
- Do not store a `?gwtoken=` link's token without verifying it, and do not add a shared unauthenticated cap on the shell.
- Do not treat a `Tailscale-*`/forwarded header as a credential or as proof of identity — it can only LOWER trust.
