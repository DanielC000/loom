# 776fc8c9 — one cost account for the inert-diff-skip reclassification path, not two contradictory ones

## Narrative

Card 776fc8c9 folds a second, contradictory cost account that used to live 45 lines below the `preWaitBranchHead` capture into a single account there: when `inertSkip` ends up true, this path makes THREE `resolveGitRef` calls total — `preWaitBranchHead` (unconditional, the instant the block is entered), plus `postWaitHead` and `postWaitBranchHead`, both gated on `inertSkip` and taken only once the repo guard is granted. `acquireRepoGuardOnly` resolving instantly (the common, uncontended case) makes all three cheap — but does NOT make the two later reads "the only added cost", the way an earlier version of this comment claimed: `postWaitBranchHead` is a second, distinct read the `db413510` card added, never folded into that older count (see `db413510`'s own record). The short-circuit requires BOTH pairs to match, not just the main-head pair — `postWaitHead === gateBaseMainHead` AND `postWaitBranchHead === preWaitBranchHead` — so either mismatch, or a failed resolve on either side, routes into re-derivation; a stale skip is no longer possible through the branch side alone.

CURRENT TRIGGER SET for the reap that precedes re-union (documented per card 776fc8c9 — was never written down as it grew): the reap is only reached via the post-wait mismatch check plus `postWaitHead && !preLanded`, so it fires whenever `postWaitHead` resolved AND `!preLanded` AND at least one of — (1) main moved during the guard wait (`postWaitHead !== gateBaseMainHead`, the original `ac7aad04` trigger), or (2) the branch moved during the guard wait (`postWaitBranchHead !== preWaitBranchHead`, added alongside the `db413510` branch-blind fix) — which INCLUDES the benign inverted window where classification already accounted for the move, since this check can't distinguish "moved after classification" from "moved before, already seen" — or (3) the branch-tip re-read itself failed (`!postWaitBranchHead`, fail-closed). Verified against commit `7dd30886` (same day, this exact function): that commit touches ONLY `reunionAtAdmission`'s own separate emit-compare re-derivation further below, which does no worktree write and calls no reap of its own — it adds no fourth trigger to this reap call. The worker's pty is still live here (this card's own founding premise), so a dev server it started inside its own worktree can be reaped under (2)/(3) in cases the original main-moved-only trigger left alone. Judged NOT a defect (Code Review + card 776fc8c9): worktree-scoped and worker-pid-excluded, identical in kind to the already-shipped main-moved reap. If this needs narrowing, that's a separate card — not decided here.

## Do not

- Do not treat `postWaitHead`/`postWaitBranchHead` as two independent added costs on this path — account for all three `resolveGitRef` calls (including `preWaitBranchHead`) together; a split account has already gone stale here once.
- Do not narrow the reap's trigger set without a separate card — it deliberately fires on main-moved, branch-moved, or a failed branch-tip re-read alike, and reaping a live worker's own dev server under those is judged not a defect.
