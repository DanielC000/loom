# d099087f — a branch tip that moves T1→T2→T1 inside a gate is detected by the reflog delta, not a head compare

Extends 975c774b / c59165b8 (pinned gated tip, outcome `gate-tip-moved`, in `NEVER_CACHED_OUTCOMES`). A worker that commits T2 mid-gate and resets back to T1 before settle leaves the settle head equal to the pre-spawn head AND the live tip equal to the pinned tip, so a PASS earned on mixed T1/T2 content squashed T1.

## Do not

- Do not "fix" this by comparing `post.head !== gatePreStamp.head` in the `runGateSeq` wrapper (the card's own suggestion): in the ABA case the two are EQUAL, so that check is inert here. It would only re-flag a plain move that the pinned-tip check already refuses.
- Do not read only `refs/heads/<branch>`'s reflog: the gate reads the WORKTREE's HEAD, and a HEAD-only round trip (detach → commit → checkout back, another branch and back, an aborted rebase) writes no branch entry. Snapshot BOTH the branch reflog and the worktree's own HEAD reflog (`snapshotGateReflogs`), and take the snapshot FIRST in `captureGatedTip`.
- Do not reset `gateHeadLeftDuringRun` between gate links: it is sticky across the single-file and resumed links, like `pinnedGateTip`, or a later partial link launders an ABA on an earlier one. It IS reset (with `gateHeadReturned`/`gateHeadLeftAt`, and fresh reflog snapshots from `captureGatedTip`) at the transient whole-gate re-run's re-pin, exactly like `gateWorktreeChanged`. An earlier call to keep it sticky there too was REVERSED: a whole-gate re-run on the re-pinned tip is complete evidence for that tip (c59165b8's contract), and sticky refused that re-run's pass, failing merge-confirm-gated-tip-squash.mjs scenario (F).
- Do not treat every reflog growth as a move: `gateReflogLeftHead` flags only new entries whose sha differs from the pre-spawn head (a `reset --hard HEAD` no-op must not refuse). The delta is anchored on the before-snapshot's newest entry by position AND sha, not on length alone, so an expiry or rewrite during the gate cannot hide a round trip; an unreadable, shrunken or unanchored reflog fails closed.
- Do not leave the `run_gate` self-check out: its stamps (start/admit/settle) all show the same head after an ABA, so a reused green would skip the merge gate. `describeGateHeadCurrency` takes a `roundTrip` flag (reflog snapshot at admission vs settle) and yields `headCurrent:false`, which makes the result non-reusable.
- Do not add a new outcome: the refusal is `gateTipMoved` with `movedAndBack:true`, so classification stays `gate-tip-moved` and stays never-cached.

- Do not let `roundTrip` run ahead of `describeGateHeadCurrency`'s other checks: it decides ONLY where the stamps cannot see a move (settle === admit, including the queue-wait-relabel case). The order is null-stamp UNKNOWN, then admit-vs-settle RACY, then `roundTrip`, then start-vs-settle CLEAN/RELABELED, so a plain mid-run commit that never returns keeps 39196378's RACY wording (`run-gate-head-currency.mjs` pins that). Card 92dcd9f1 made this true: the start==settle CLEAN shortcut used to run first, so a tree that moved in the queue wait and back mid-run (start == settle ≠ admit, including the uncommitted-edit variant that writes no reflog entry) read `headCurrent:true`. Do not move that shortcut back above the admit-vs-settle check.
- Do not label a HEAD-only move that never returns (worktree left detached at T2, branch ref still T1) `movedAndBack`: only a move whose settle worktree HEAD is back at the pre-spawn head is; the other is refused as an ordinary `gateTipMoved` naming the worktree HEAD it was left on.

- Do not let a gate FAIL whose FINAL link left the gated commit (a plain branch move, or a HEAD-only move that never returns) or whose reflog snapshot was unreadable fall back to the pre-forward `verdictIdentity` (card 01777ceb): a later reset to that sha would replay the red as a cacheHit. It is cached under `void:<opId>` (`gateIdentityVoid`), so a re-call re-gates and still announces identity-mismatch. The flag is PER-LINK (`gateLinkLeft`, reset by `captureGatedTip`) — an earlier link's move must not void a later clean link's identity (`merge-confirm-verdict-cache-retry-links.mjs` pins that).
- Do not count a link as clean unless its pre-spawn worktree head (`gatePreStamp.head`) equals its `gatedTip` (read from the BRANCH ref) AND it did not leave during its run — ONE predicate (`gateFinalLinkState`) shared by both sides: a FAIL from a not-clean FINAL link is void-identity cached, and a PASS with ANY contributing link not clean (sticky `anyLinkPreHeadOff`/`anyLinkPreUnverified`, reset at the whole-gate re-run's re-pin: a composed PASS carries steps that passed on earlier links and are not re-run by the final one) is refused as `gateTipMoved` (a worktree detached BEFORE the gate ran the gate on T3 while the ref names T1; squashing the ref would land never-gated content). Do not fix only the FAIL side, and do not fix only the merge gate: the `run_gate` self-check stamps the WORKTREE head only, so a detached self-check read `headCurrent:true` and the merge REUSED it (landing the branch ref's never-gated content). The head-vs-branch-ref comparison is the ONE pure helper `gateHeadOnBranch` (git/worktrees.ts), fed by `captureGatedTip`, by `runWorkerGate`'s settle (`headCurrent:false`), and by the reuse proof (`head-off-branch` refusal, which also covers self-checks recorded before this rule). Do not add a fourth local head-vs-ref check. Do not leave the REUSE squash unpinned: `reuseExpectedTip` (the tip the reuse proof saw) rides into `mergeBranch` as `expectedBranchTip`, the real-gate path's 975c774b pin, or a commit between the proof and the lock lands as an unverified `reused:true`. Do not give `gateTipMoved.live` two meanings: it is ALWAYS the branch's live tip (a worktree HEAD off it is `worktreeHead` + `headOffBranch`). And an unreadable reflog on the `run_gate` self-check is "could not verify" (`headCurrent:false`, card c3e1bfc3), never "moved and came back".
- Do not label an unreadable reflog snapshot a round trip: it is `gateTipUnverified` ("could not verify"), excluded from `gateRoundTripFail`, and a FAIL is not cached under it. A PASS still fails closed on it, as before.

Known false refusal: a reflog expiry (e.g. `gc --auto` on an old worktree) that shrinks the reflog or breaks the position anchor during a gate reads as "moved". Rare, fails closed, costs one re-gate.

Known limit: a repo with `core.logAllRefUpdates=false` records no reflog, so the ABA round trip is invisible there (the snapshots compare equal).
